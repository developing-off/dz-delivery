MDM Express API for Node.js and PHP

MDM Express stores your products and ships them. With dz-delivery, the mdm provider uses its v2 API (parcels, geography, offices) with the same code as every other carrier.

Install

TypeScript · npm
npm install @dz-delivery/core
PHP · Composer
composer require dz-delivery/sdk

Node.js ≥ 18 (zero dependencies) or PHP ≥ 8.2 (Guzzle 7). The same code then works for the other carriers: only the client configuration changes.

MDM Express in TypeScript / Node.js

TypeScript
import { createClient, isShippingError } from '@dz-delivery/core';

const mdm = createClient('mdm', {
  apiKey: process.env.MDM_API_KEY!,
  storeId: process.env.MDM_STORE_ID!,  // STR-…
});

const quote = await mdm.getFees({ toWilayaId: 16, toCommuneId: 'Bab Ezzouar' });

try {
  const parcel = await mdm.createParcel({
    recipientName: 'Mohamed Amine',
    phone: '0550123456',
    address: 'Cité 221 lots, n°98',
    wilayaId: 16,
    communeName: 'Bab Ezzouar',
    // products stocked at MDM: their catalog id (PRD-…)
    productList: [{ name: 'T-shirt', quantity: 1, productId: 'PRD-B5C63A' }],
    price: 2500,
  });

  const { parcel: current, events } = await mdm.track(parcel.trackingNumber);
} catch (err) {
  if (isShippingError(err)) console.error(err.code, err.message);
}

// Delivered parcels, filtered by MDM
const delivered = await mdm.listParcels({ status: 'delivered', pageSize: 50 });

MDM Express in PHP / Laravel

PHP
use DzDelivery\ClientFactory;
use DzDelivery\Errors\ShippingError;

$mdm = ClientFactory::create('mdm', [
    'apiKey'  => getenv('MDM_API_KEY'),
    'storeId' => getenv('MDM_STORE_ID'),
]);

try {
    $parcel = $mdm->createParcel([
        'recipientName' => 'Mohamed Amine',
        'phone'         => '0550123456',
        'address'       => 'Cité 221 lots, n°98',
        'wilayaId'      => 16,
        'communeName'   => 'Bab Ezzouar',
        'productList'   => [['name' => 'T-shirt', 'quantity' => 1, 'productId' => 'PRD-B5C63A']],
        'price'         => 2500,
    ]);

    $result = $mdm->track($parcel->trackingNumber);
} catch (ShippingError $e) {
    echo "{$e->code}: {$e->getMessage()}";
}

MDM Express statuses → unified statuses

The SDK maps MDM status slugs (read live from GET /api/v2/shipping/parcels/metadata, October 2026) to unified statuses. The status filter of listParcels uses the same table: every MDM slug of the requested status is filtered by MDM.

Good to know about the MDM Express API

  • Tested live (October 2026, read-only): wilayas, communes, offices, fees, list, tracking, errors.
  • Fulfillment: MDM ships products stocked in its own warehouse. Every productList line must carry its MDM catalog id; an unknown product → VALIDATION_ERROR on productList.
  • price is what the recipient pays: MDM adds no delivery fee on top.
  • MDM has no “order reference” field: orderId is written to the notes (Ref: …) and can still be filtered with listParcels({ orderId }).
  • The baseUrl must use HTTPS.

Detailed native mapping (endpoints, fields, statuses): PROVIDERS.md.

MDM Express FAQ

Where do I find my MDM API key and storeId?

In the MDM dashboard: the API key in the API settings, the storeId (STR-…) in your store.

Can I ship a product that is not stocked at MDM?

No: MDM rejects products outside its catalog. Add the product to MDM first, then use its PRD-… id.

How do I cancel an MDM parcel?

The API has no cancellation: cancelParcel returns NOT_SUPPORTED. Cancel from the MDM dashboard.
