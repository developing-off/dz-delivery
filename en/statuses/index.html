Parcel statuses, models and error codes

Every Algerian carrier has its own statuses: French labels at Yalidine, numeric codes at Maystro, their own states at ZRExpress, Ecotrack or NoEST. dz-delivery maps them to seven unified statuses, with the same models and error codes in TypeScript and PHP.

Mapping a native status (webhooks, imports)

The mappers are exported: use them when you receive a native status outside track(), for example in a Maystro webhook.

TypeScript
import { mapYalidineStatus, mapMaystroStatus, PARCEL_STATUSES } from '@dz-delivery/core';

mapYalidineStatus('Sorti en livraison');  // 'in_transit'
mapMaystroStatus(41);                     // 'delivered' (code or name)
PARCEL_STATUSES;                          // the 7 statuses, in order
// Also: mapZRExpressStatus, mapEcotrackStatus, mapNoestStatus, mapEcomStatus, mapMdmStatus, mapElogistiaStatus
PHP
use DzDelivery\Support\StatusMapper;
use DzDelivery\Models\ParcelStatus;

StatusMapper::map('yalidine', 'Sorti en livraison');  // 'in_transit'
StatusMapper::maystro(41);                             // 'delivered' (code or name)
ParcelStatus::DELIVERED;                               // constants, ParcelStatus::ALL for the list

Error codes

Every failure is thrown as a ShippingError (fields in Models). Its code is one of:

codeWhen
AUTH_FAILED401/403, missing or invalid credentials.
VALIDATION_ERROR400/422, or SDK-side input validation failure (before any HTTP call).
NOT_FOUND404, parcel / location not found, or name resolution (wilayaName, communeName) failed.
RATE_LIMITED429.
NOT_SUPPORTEDThe carrier does not support this operation (e.g. cancellation).
PROVIDER_ERROR5xx or an unexpected/unparseable carrier response.
NETWORK_ERRORTimeout, DNS, connection refused.
UNKNOWNAnything else.

Default HTTP → code mapping: 400, 422 → VALIDATION_ERROR, 401, 403 → AUTH_FAILED, 404 → NOT_FOUND, 429 → RATE_LIMITED, 5xx → PROVIDER_ERROR, other 4xx → UNKNOWN.

Handling examples (retry on RATE_LIMITED, showing validation errors): PHP guide.

Conventions

TopicRule
NamingcamelCase for fields and methods in both TS and PHP (PHP objects expose public readonly properties with the same names).
IDsAll IDs returned by the SDK are strings (carriers use UUIDs, integers or codes). Inputs accept string | int.
MoneyAmounts are in DZD, as numbers (dinars, not centimes). currency is always "DZD".
Weight / sizeWeight in kg, dimensions in cm.
DatesISO 8601 strings with timezone (e.g. 2025-12-23T15:23:54+00:00) in both TS and PHP.
PhonesStrings. Providers normalize to the carrier’s format (e.g. 0550123456 ↔ +213550123456).
Optional? = optional. Absent optional values are undefined (TS) / null (PHP).
AsyncTS methods return Promise<T>. PHP methods are synchronous and return T.
ErrorsAll failures are thrown as ShippingError (see Error codes). Never null / false to signal an error.

The raw field

Every returned model (Parcel, TrackingEvent, FeeQuote, Location, ShippingError) may carry an optional raw field with the unmodified native API response (or the relevant fragment).

  • raw is for power users and debugging. Its shape is not part of the contract and may change when the carrier changes its API.
  • Application code should not depend on raw for core logic.
  • raw is populated by default; the client option includeRaw: false disables it.

The ShippingProvider interface

Every client implements the same interface: ShippingProvider in TypeScript, ShippingProviderInterface in PHP.

TypeScript
export type ParcelStatus =
  | 'pending' | 'created' | 'in_transit' | 'delivered'
  | 'returned' | 'cancelled' | 'unknown';

export interface HealthCheckResult {
  ok: true;
  provider: string;
  /** Round-trip duration in milliseconds. */
  latencyMs: number;
}

export interface ShippingProvider {
  readonly name: string; // 'zrexpress' | 'yalidine' | ...
  createParcel(input: ParcelInput): Promise<Parcel>;
  track(trackingNumber: string): Promise<TrackResult>;
  getFees(query: FeeQuery): Promise<FeeQuote>;
  getWilayas(): Promise<Location[]>;
  getCommunes(wilayaId: string | number): Promise<Location[]>;
  getStopDesks(query: StopDeskQuery): Promise<StopDesk[]>;
  listParcels(query?: ParcelListQuery): Promise<ParcelListPage>;
  cancelParcel(trackingNumberOrId: string): Promise<void>;
  healthCheck(): Promise<HealthCheckResult>;
}
PHP
namespace DzDelivery\Contracts;

interface ShippingProviderInterface
{
    public function getName(): string;
    public function createParcel(ParcelInput|array $input): Parcel;
    public function track(string $trackingNumber): TrackResult;
    public function getFees(FeeQuery|array $query): FeeQuote;
    /** @return Location[] */
    public function getWilayas(): array;
    /** @return Location[] */
    public function getCommunes(string|int $wilayaId): array;
    /** @return StopDesk[] */
    public function getStopDesks(StopDeskQuery|array $query): array;
    public function listParcels(ParcelListQuery|array|null $query = null): ParcelListPage;
    public function cancelParcel(string $trackingNumberOrId): void;
    public function healthCheck(): HealthCheckResult;
}

Method behavior

  • createParcel: validates required fields client-side (VALIDATION_ERROR before any HTTP call) and resolves wilayaName / communeName / wilaya codes to provider IDs. If the carrier only returns an ID on creation, the provider may do a follow-up read to fill trackingNumber and status.
  • track: returns the current Parcel plus history. If the carrier needs an internal ID for history, the provider resolves it from the tracking number.
  • getFees: returns a single quote for the requested destination and mode. NOT_FOUND if the destination has no rate.
  • getWilayas / getCommunes: return only deliverable locations when the carrier exposes that information. Results may be cached in memory for the client’s lifetime.
  • cancelParcel: accepts a tracking number or an internal ID. NOT_SUPPORTED if the carrier cannot cancel, VALIDATION_ERROR / PROVIDER_ERROR if the parcel is past the cancellable state. Returns void because some carriers answer 204 No Content: call track() afterwards if you need the new status.
  • getStopDesks: lists the stop desks / pickup points of a wilaya (optionally one commune). VALIDATION_ERROR when a carrier needs communeId and it is missing, NOT_SUPPORTED when the carrier exposes no listing. May throw NOT_FOUND with an actionable details hint when a commune filter yields no desks but the wilaya still has some (typical for ZRExpress hubs).
  • listParcels: paginated list of the account’s parcels with their unified status, without history (call track() for that). NOT_SUPPORTED when the carrier exposes no listing. Prefer webhooks over aggressive polling when available.
  • healthCheck: probes credentials and connectivity with a lightweight authenticated request (the wilayas listing). Always hits the network (bypasses the cache). Returns { ok: true, provider, latencyMs }, otherwise throws ShippingError (AUTH_FAILED, NETWORK_ERROR, RATE_LIMITED, …). Never throws NOT_SUPPORTED.

Outside the unified contract

Intentionally not part of the common interface: catalog endpoints (products, categories, stock), parcel updates (address, amount, products), exchanges, refunds, pickup bags, claims, customers, treasury and payments, reports, and webhook endpoint management. They may come later as optional, carrier-specific modules that do not change ShippingProvider.

Richer carrier features ship as extras on the concrete provider class, for example ZRExpress bulk create/delete, labels and webhook verification (ZRExpress page, ZREXPRESS.md).

This contract is versioned (v0.1): breaking changes to the models or the interface require a version bump and a matching release of both packages.
