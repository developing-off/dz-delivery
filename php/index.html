Intégrer la livraison en PHP / Laravel

Appelez Yalidine, ZRExpress, Maystro, Ecotrack (DHD…), NoEST, E-com Delivery, MDM et Elogistia depuis votre application PHP avec une seule API : mêmes méthodes, mêmes modèles, mêmes statuts.

Le contrat complet (modèles, statuts, erreurs) est décrit sur la page Statuts, modèles et erreurs ; le mapping propre à chaque transporteur dans PROVIDERS.md.

1. Installer le SDK PHP

Prérequis : PHP ≥ 8.2 et Guzzle 7 (installé par Composer). Le paquet est publié sur Packagist :

Composer
composer require dz-delivery/sdk

Vous travaillez sur le SDK lui-même ? Pointez votre application vers une copie locale avec un dépôt de type path (les modifications du SDK sont visibles immédiatement) :

composer.json
{
  "repositories": [
    { "type": "path", "url": "../dz-delivery/packages/php" }
  ],
  "require": {
    "dz-delivery/sdk": "*@dev"
  }
}

Tout se trouve sous l’espace de noms DzDelivery\ (PSR-4).

2. Configurer un transporteur

Créez un client par transporteur avec ClientFactory::create($provider, $options). Gardez les identifiants dans des variables d’environnement ou un fichier .env (voir .env.example) : ne les écrivez jamais en dur et ne les commitez pas.

PHP
use DzDelivery\ClientFactory;

$zr = ClientFactory::create('zrexpress', [
    'apiKey' => getenv('ZREXPRESS_API_KEY'),   // envoyé en X-Api-Key
    'tenant' => getenv('ZREXPRESS_TENANT'),    // envoyé en X-Tenant
]);

$yalidine = ClientFactory::create('yalidine', [
    'apiId'        => getenv('YALIDINE_API_ID'),     // envoyé en X-API-ID
    'apiToken'     => getenv('YALIDINE_API_TOKEN'),  // envoyé en X-API-TOKEN
    'fromWilayaId' => 16,                            // ou 'fromWilayaName' => 'Alger'
]);

$maystro = ClientFactory::create('maystro', [
    'apiToken' => getenv('MAYSTRO_API_TOKEN'),  // envoyé en Authorization: Token <apiToken>
]);

$dhd = ClientFactory::create('ecotrack', [
    'token'   => getenv('ECOTRACK_TOKEN'),  // envoyé en Authorization: Bearer <token>
    'courier' => 'dhd',                     // ou 'baseUrl' => 'https://<tenant>.ecotrack.dz'
    // 'autoValidate' => true,              // valide chaque commande auprès du livreur dès sa création
]);

$noest = ClientFactory::create('noest', [
    'apiToken' => getenv('NOEST_API_TOKEN'),  // envoyé en Authorization: Bearer <apiToken>
    'userGuid' => getenv('NOEST_USER_GUID'),  // GUID partenaire, envoyé en user_guid
    // 'autoValidate' => true,                // valide chaque commande auprès de NOEST dès sa création
]);

$ecom = ClientFactory::create('ecom', [
    'apiKey'   => getenv('ECOM_API_KEY'),    // KEY, envoyé en X-API-Key
    'apiToken' => getenv('ECOM_API_TOKEN'),  // Token, envoyé en X-API-Token
    // 'autoValidate' => true,               // crée les colis déjà confirmés
]);

$mdm = ClientFactory::create('mdm', [
    'apiKey'  => getenv('MDM_API_KEY'),   // envoyé en x-api-key
    'storeId' => getenv('MDM_STORE_ID'),  // STR-…, requis pour créer des colis
]);

$elogistia = ClientFactory::create('elogistia', [
    'apiKey' => getenv('ELOGISTIA_API_KEY'),  // envoyé dans la query string (choix d'Elogistia)
]);

Chaque client implémente DzDelivery\Contracts\ShippingProviderInterface : typez vos dépendances sur l’interface et changez de transporteur sans toucher au reste du code.

3. Méthodes

Toutes les méthodes acceptent soit un tableau, soit l’objet modèle correspondant (ParcelInput, FeeQuery, StopDeskQuery). Tous les modèles renvoyés exposent des propriétés publiques readonly en camelCase. Toute erreur lève DzDelivery\Errors\ShippingError (voir §5).

3.1 createParcel(ParcelInput|array $input): Parcel

Livraison à domicile :

PHP
$parcel = $client->createParcel([
    'recipientName' => 'Client Test',
    'phone'         => '0550123456',
    'address'       => '12 rue des Tests',
    'wilayaId'      => 16,               // ou 'wilayaName' => 'Alger'
    'communeName'   => 'Bab Ezzouar',    // ou 'communeId' => ...
    'productList'   => [
        ['name' => 'Mug', 'quantity' => 2],
        ['name' => 'T-shirt'],
    ],                                   // ou 'productName' => 'T-shirt'
    'price'         => 3200,             // montant payé par le destinataire, en DZD
    'weight'        => 1.5,
    'orderId'       => 'ORD-1001',
]);

echo $parcel->trackingNumber;  // à enregistrer avec votre commande
echo $parcel->status;          // en général 'pending' juste après la création

Livraison en stop desk (bureau) : récupérez l’id du bureau avec getStopDesks et passez-le en stopDeskId.

PHP
$desks = $yalidine->getStopDesks(['wilayaId' => 16, 'communeId' => 1630]);

$parcel = $yalidine->createParcel([
    'recipientName' => 'Client Test',
    'phone'         => '0550123456',
    'address'       => 'Retrait au bureau',
    'wilayaId'      => 16,
    'communeId'     => 1630,
    'productName'   => 'T-shirt',
    'price'         => 2500,
    'isStopDesk'    => true,
    'stopDeskId'    => $desks[0]->id,
]);

echo $result->parcel->status;               // statut unifié actuel

}

PropriétéTypeDescription

3.3 getFees(FeeQuery|array $query): FeeQuote

PHP
$quote = $yalidine->getFees([
    'toWilayaId'  => 31,
    'toCommuneId' => 3101,   // tarifs par commune chez Yalidine et Maystro
    'weight'      => 2,
    'length'      => 50,     // cm : Yalidine facture le poids volumétrique s'il est plus élevé
    'width'       => 40,
    'height'      => 30,
]);

echo $quote->deliveryFee;   // 950 si oversize_fee = 50 DA/kg (voir ci-dessous)
echo $quote->stopDeskFee;
echo $quote->returnFee;

Entrée (FeeQuery) :

ChampTypeRequisNotes
toWilayaIdint|stringouiCode 1–58 ou id du transporteur.
toCommuneIdint|stringnonYalidine / Maystro : sans lui, la première commune de la wilaya est utilisée.
fromWilayaIdint|stringnonYalidine : remplace le fromWilayaId du client.
weightnumbernonkg.
length, width, heightnumbernoncm. Utilisés par Yalidine uniquement.
isStopDeskboolnontrue : deliveryFee est le tarif stop desk.

Sortie (FeeQuote) :

PropriétéTypeDescription
deliveryFeeint|floatTarif pour le mode demandé (domicile ou stop desk).
stopDeskFeeint|float|nullTarif stop desk, quand le transporteur le fournit.
returnFeeint|float|nullFrais de retour (Yalidine uniquement pour l’instant).
currencystringToujours DZD.
rawmixedRéponse native.

Surpoids Yalidine. Poids facturé = max(weight, length × width × height × 0.0002) ; le poids volumétrique n’est utilisé que si les trois dimensions sont fournies. Au-delà de 5 kg, (facturé − 5) × oversize_fee (arrondi au dinar supérieur) s’ajoute aux deux tarifs. Dans l’exemple : 50 × 40 × 30 × 0,0002 = 12 kg → (12 − 5) × 50 = 350 DA, en plus d’un tarif domicile de 600 DA.

ZRExpress et Maystro ignorent poids et dimensions. Aucun tarif pour le mode demandé → NOT_FOUND.

3.6 getStopDesks(StopDeskQuery|array $query): array

Liste les stop desks / points relais où le colis peut être retiré. Utilisez l’id renvoyé comme stopDeskId dans createParcel.

PHP
// ZRExpress : commencez par la wilaya seule, le filtre commune renvoie souvent zéro hub.
$desks = $client->getStopDesks(['wilayaId' => 16]);

foreach ($desks as $desk) {
    echo "{$desk->id}  {$desk->name}  {$desk->address}\n";
}

Entrée (StopDeskQuery) :

ChampTypeRequisNotes
wilayaIdint|stringouiCode 1–58, id du transporteur ou nom.

3.8 cancelParcel(string $trackingNumberOrId): void

PHP

  • ZRExpress : accepte l’UUID ou le numéro de suivi.

3.9 healthCheck(): HealthCheckResult

Vérification légère et authentifiée (liste des wilayas). Appelle toujours le réseau (ignore le cache en mémoire). En cas de succès, renvoie { ok: true, provider, latencyMs } ; en cas d’échec, lève une ShippingError (AUTH_FAILED, NETWORK_ERROR…).

PHP

// $health->ok === true
// $health->provider  // 'yalidine' | ...
// $health->latencyMs // millisecondes

4. Statuts de colis

Chaque statut natif des transporteurs est converti en l’un de ces statuts unifiés :

StatutSignification
pendingEnregistré mais pas encore confirmé / prêt pour l’enlèvement.
createdConfirmé, prêt à être enlevé ou expédié.
in_transitEnlevé et en mouvement : hub, transfert, en cours de livraison, tentative échouée…
deliveredLivré (COD encaissé).
returnedRetourné ou en retour vers l’expéditeur.
cancelledAnnulé / supprimé avant livraison.
unknownPas encore mappé. Jamais une erreur : consultez $event->label / ->raw.

Les constantes sont dans DzDelivery\Models\ParcelStatus (ParcelStatus::DELIVERED, …, ParcelStatus::ALL).

Pour convertir vous-même un statut natif (par exemple reçu par webhook), utilisez DzDelivery\Support\StatusMapper :

PHP
use DzDelivery\Support\StatusMapper;

StatusMapper::map('yalidine', 'Sorti en livraison');  // 'in_transit'
StatusMapper::maystro(41);                             // 'delivered' (code ou nom)

Détail des statuts et exemples par transporteur : Statuts de colis unifiés. Tables complètes natif → unifié : PROVIDERS.md.

5. Gestion des erreurs

Tout lève DzDelivery\Errors\ShippingError (qui étend \RuntimeException).

PropriétéTypeDescription
codestringUn des codes ci-dessous (une chaîne, pas un entier).
getMessage()stringMessage du transporteur quand il existe.
httpStatus?intStatut HTTP de l’appel en échec.
details?arrayPar exemple les erreurs de validation [['field' => 'phone', 'message' => '…'], …].
rawmixedCorps d’erreur natif.
provider?stringClé du transporteur.
retryAfter?intRATE_LIMITED uniquement : secondes d’attente, issues de l’en-tête Retry-After quand il est envoyé.
CodeQuand
AUTH_FAILEDIdentifiants manquants ou invalides (401 / 403).
VALIDATION_ERROREntrée invalide (vérifiée avant l’appel), 400 / 422, ou colis refusé par le transporteur.
NOT_FOUND404, colis, wilaya ou commune inconnus.
RATE_LIMITED429. Limites Yalidine par défaut : 5 req/s, 50/min, 1 000/h, 10 000/jour.
NOT_SUPPORTEDLe transporteur ne propose pas cette opération.
PROVIDER_ERROR5xx ou réponse inattendue.
NETWORK_ERRORTimeout, DNS, connexion refusée.
UNKNOWNTout le reste.

Le SDK ne relance jamais un appel de lui-même. Une relance simple pour les limites de débit :

PHP
use DzDelivery\Errors\ShippingError;

function withRetry(callable $call, int $attempts = 3): mixed
{
    for ($i = 1; ; $i++) {
        try {
            return $call();
        } catch (ShippingError $e) {
            if ($e->code !== ShippingError::RATE_LIMITED || $i >= $attempts) {
                throw $e;
            }
            sleep($e->retryAfter ?? 2 ** $i);
        }
    }
}

$wilayas = withRetry(fn () => $client->getWilayas());

Ne relancez pas aveuglément createParcel sur NETWORK_ERROR : le colis existe peut-être déjà. Vérifiez d’abord, ou appuyez-vous sur votre orderId.

Afficher les erreurs de validation à l’utilisateur :

PHP
try {
    $client->createParcel($input);
} catch (ShippingError $e) {
    if ($e->code === ShippingError::VALIDATION_ERROR) {
        foreach ($e->details ?? [] as $d) {
            $errors[$d['field'] ?? 'general'][] = $d['message'];
        }
    } else {
        error_log("[{$e->provider}] {$e->code}: {$e->getMessage()}");
        throw $e;
    }
}

6. Exemple Laravel

config/services.php :

config/services.php
'dz_delivery' => [
    'default' => env('DZ_DELIVERY_PROVIDER', 'yalidine'),
    'zrexpress' => ['apiKey' => env('ZREXPRESS_API_KEY'), 'tenant' => env('ZREXPRESS_TENANT')],
    'yalidine' => [
        'apiId' => env('YALIDINE_API_ID'),
        'apiToken' => env('YALIDINE_API_TOKEN'),
        'fromWilayaId' => (int) env('YALIDINE_FROM_WILAYA_ID', 16),
    ],
    'maystro' => ['apiToken' => env('MAYSTRO_API_TOKEN')],
],

app/Providers/ShippingServiceProvider.php (à enregistrer dans bootstrap/providers.php ou config/app.php) :

app/Providers/ShippingServiceProvider.php
namespace App\Providers;

use DzDelivery\ClientFactory;
use DzDelivery\Contracts\ShippingProviderInterface;
use Illuminate\Support\ServiceProvider;

final class ShippingServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        // Transporteur par défaut, injectable partout. Une instance par app = caches de localités partagés.
        $this->app->singleton(ShippingProviderInterface::class, function () {
            $provider = config('services.dz_delivery.default');

            return ClientFactory::create($provider, config("services.dz_delivery.$provider"));
        });
    }
}

Contrôleur :

PHP
use DzDelivery\Contracts\ShippingProviderInterface;
use DzDelivery\Errors\ShippingError;

final class ShipmentController
{
    public function store(Order $order, ShippingProviderInterface $shipping)
    {
        try {
            $parcel = $shipping->createParcel([
                'recipientName' => $order->customer_name,
                'phone' => $order->phone,
                'address' => $order->address,
                'wilayaId' => $order->wilaya_code,
                'communeName' => $order->commune,
                'productName' => $order->summary(),
                'price' => $order->total,
                'orderId' => (string) $order->id,
            ]);
        } catch (ShippingError $e) {
            return back()->withErrors(['shipping' => $e->getMessage()]);
        }

        $order->update(['tracking' => $parcel->trackingNumber, 'carrier' => $parcel->provider]);

        return back();
    }
}

Plusieurs transporteurs à la fois ? Liez plutôt une petite factory (par exemple fn (string $p) => ClientFactory::create($p, config("services.dz_delivery.$p"))) et gardez un client par transporteur.

7. Webhooks Maystro

track() lit une commande Maystro et son historique à la demande. Pour être notifié au lieu d’interroger l’API, Maystro peut aussi pousser les changements de statut vers une URL HTTPS configurée dans l’application Maystro (Paramètres → Webhooks). L’événement utile est OrderStatusChanged, dont le payload vaut { "id": "<uuid de la commande>", "status": <code numérique> }. payload.id est l’id de commande renvoyé en $parcel->id par createParcel.

Ce que dit la documentation Maystro du corps de la requête (aucune requête réelle capturée pour l’instant : à considérer comme non vérifié) :

  • l’événement JSON est encodé en base64 et envoyé dans message.data ;
  • le texte dit de le décoder « deux fois en base64 », alors que leur exemple Django ne le décode qu’une fois. L’exemple ci-dessous gère les deux cas.
public/maystro-webhook.php
<?php
// public/maystro-webhook.php

require __DIR__ . '/../vendor/autoload.php';

use DzDelivery\Support\StatusMapper;

$body = json_decode(file_get_contents('php://input') ?: '', true);
$data = $body['message']['data'] ?? null;

$event = null;
if (is_string($data)) {
    $decoded = base64_decode($data, true);
    $event = json_decode((string) $decoded, true);
    if (!is_array($event)) {                       // décodé une fois, c'est encore du base64
        $event = json_decode((string) base64_decode((string) $decoded, true), true);
    }
}

if (!is_array($event)) {
    http_response_code(400);
    exit;
}

if (($event['event'] ?? null) === 'OrderStatusChanged') {
    $orderId = (string) ($event['payload']['id'] ?? '');
    $status = StatusMapper::maystro($event['payload']['status'] ?? null);  // ex. 41 → 'delivered'

    // mettre à jour votre commande dont carrier_id = $orderId ...
}

http_response_code(201);

La documentation ne décrit aucune signature des requêtes webhook. Protégez l’endpoint vous-même, par exemple avec un long secret dans l’URL (/maystro-webhook.php?key=…) vérifié avant tout traitement. Voir aussi les webhooks sur la page Maystro.

8. Tester votre intégration

Passez un handler Guzzle via l’option handler pour remplacer le réseau par des réponses préparées :

PHP
use DzDelivery\ClientFactory;
use GuzzleHttp\Handler\MockHandler;
use GuzzleHttp\HandlerStack;
use GuzzleHttp\Psr7\Response;

$mock = new MockHandler([
    new Response(200, ['Content-Type' => 'application/json'], json_encode([
        'has_more' => false,
        'data' => [['id' => 16, 'name' => 'Alger', 'zone' => 1, 'is_deliverable' => 1]],
    ])),
]);

$client = ClientFactory::create('yalidine', [
    'apiId' => 'test', 'apiToken' => 'test', 'fromWilayaId' => 16,
    'handler' => HandlerStack::create($mock),
]);

$wilayas = $client->getWilayas();   // servi par le mock, aucun appel HTTP

Ajoutez GuzzleHttp\Middleware::history($container) à la pile pour vérifier les requêtes envoyées. Des réponses natives réalistes pour chaque transporteur sont disponibles dans docs/fixtures/.

Dans le code applicatif, typez sur ShippingProviderInterface : vous pourrez alors injecter votre propre implémentation factice dans les tests au lieu de simuler HTTP.

9. Extras ZRExpress

La création / suppression en masse, les étiquettes et la vérification des webhooks signés sont disponibles sur ZRExpressProvider (et DzDelivery\Providers\ZRExpress\Webhook), pas sur ShippingProviderInterface. Présentation sur la page ZRExpress ; matrice complète et exemples dans ZREXPRESS.md.

use DzDelivery\Providers\ZRExpressProvider;

$zr = new ZRExpressProvider([

$bulk = $zr->createParcelsBulk([

$labels = $zr->generateLabels(['16-AAA111-ZR']);

// Webhooks : utilisez le corps brut de la requête (avant json_decode)
$raw = file_get_contents('php://input');
